# TargetのDB境界

`supabase/migrations/20261105101949_target_private_quizzes.sql`はTarget専用DBへ適用します。KGS01のデータは複製せず、KGS側が認証したメンバーID・表示名と、このアプリのテスト結果だけを保存します。

`target_private`スキーマの表にはRLSを有効にし、PUBLIC・anon・authenticatedからスキーマ・表・補助関数の権限を取り除いています。Data APIに公開する`public.target_rpc(text,text,jsonb)`だけはanonに実行を許可します。この関数は、最初に別途設定する32文字以上のランダムなサーバー専用秘密を照合し、正しい場合のみ処理します。公開用のSupabase APIキーだけではデータを取得・更新できません。

秘密の平文はGitへ保存しません。非公開設定で生成した秘密のSHA-256ダイジェストだけを、管理者が`target_private.server_credentials(singleton,key_hash)`へ登録します。秘密そのものはTargetのサーバー環境変数`TARGET_RPC_SECRET`へ設定します。ダイジェストは関数ソースに埋め込みません。初期登録前、または秘密が違う場合はRPCを拒否します。

関数は`SECURITY DEFINER`ですが、固定した`search_path`と修飾済みテーブル名を使い、動的SQLを使いません。全アクションは入力形式・サイズを検証し、サーバー秘密の検証前にはユーザー入力で表を更新しません。

Supabase Advisorは、この入口を`anon_security_definer_function_executable`としてWARNで報告します。これは独自のサーバー資格情報を照合する入口として意図した公開箇所です。秘密の照合前にデータ処理を行わず、十分強い秘密が必要なこと、固定search_path、private表への直接アクセス拒否を読み取りレビューしました。クラウドの実際のData APIでも、公開可能なキーだけと誤った秘密では403の拒否結果になることを確認しています。RLSを有効にしてポリシーを作らない6表のINFOは、直接アクセスを拒否する設定によるものです。警告が存在しないとは報告しません。

- `rate`：永続的なログイン試行制限。全体3000回/日、署名済み端末に結び付くサーバーHMAC識別子ごとに5回/5分。KGS側でも番号ごとの試行制限を継続します。
- `profile`：KGSが認証したIDの表示名を反映し、累積正解数だけを返します。
- `start`：メンバーと開始操作IDを一意にし、同じ設定の再試行は既存テストを返します。設定が異なる場合は409で拒否します。正解キーは非公開の問題データ内だけに保存し、表示用DTOへ含めません。
- `answer`：所有者と現在の問題順序を確認してDB内で採点し、解答と累積正解数を同じトランザクションで保存します。同じ問題の再送は加点しません。同じ解答操作IDに別の内容を割り当てることも拒否します。別の再試行IDも1問あたり最大32個まで記録し、無制限なマーカー増加を防ぎます。
- `ranking`：解答履歴がある参加者だけを対象に、順位・表示名・累積正解数だけを返します。出席番号、内部ID、認証情報は返しません。

テスト開始は120回/時、解答受付は1200回/時をメンバーごとに制限します。メンバー500件、テスト5万件、解答20万件、および論理ペイロード100MiBのいずれかへ達すると保存を停止します。100MiBには問題・安全な解答レスポンス・再試行IDの概算分を計上し、DBの表・インデックスの実容量とは区別します。無料枠に残量があることの保証ではありません。

テスト詳細は1日で期限切れになり、その後7日を過ぎた詳細は、新しいテストの開始時に250件まで削除します。削除してもメンバーの累積正解数は保持します。開始操作の再試行を保持する期間は、この詳細保持期間内です。

採点や容量チェックは共通のトランザクション単位のアドバイザリーロックで直列化します。独立したHTTPクライアントから連打・再送しても、同じ問題が二重に加点されることはありません。

秘密を非公開の設定で生成した後、SHA-256ダイジェストだけを管理接続から登録します。下記はプレースホルダー付きの書式であり、そのまま実行しません。

```sql
INSERT INTO target_private.server_credentials(singleton,key_hash)
VALUES(true,'<private-secret-SHA-256-hex-64-characters>')
ON CONFLICT(singleton) DO UPDATE SET key_hash=excluded.key_hash;
```
