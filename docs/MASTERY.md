# 定着率と解き直し

Section横に「定着率」「解き直し」を配置します。Target 1900は19Section、熟語1000は10Sectionです。各Sectionの分母は100項目で、定着率は定着済み件数÷100×100の整数です。未回答も分母に含みます。

本人・教材・単語番号ごとに連続正解数を0〜2で保存します。2回以上連続で正解すると定着し、間違えると0へ戻ります。一度間違えた単語は、その後2回連続で正解するまで解き直し対象です。間違えていない未回答・1回正解の単語は、未定着ですが解き直し対象には含めません。英語／日本語の方向やテスト、端末を変えても同じ単語の記録を使います。

解き直しでは、選択したSectionの範囲内にある本人の対象項目だけを出題します。10・50・100問と回答方向を選べ、対象が少なければ実際の件数で開始します。対象がなければ「この範囲に解き直す単語はありません。」と表示します。テスト開始時の対象をDB内で再確認し、回答が重なって対象が変わった場合は再試行を案内します。作成済みテストの再送は対象が変わっていても元のテストを返します。

ログインが必要です。ブラウザの保存領域へ本人の定着記録を保存せず、アカウント変更・ログアウト・認証切れで表示を破棄します。読込失敗を0%として扱いません。本人の照合は各APIでKGSへ問い合わせ、別の所有者IDや正解フラグをブラウザから受け取りません。

DBは既存のTarget専用プロジェクト内のprivate領域を使用します。各回答の受理・得点・単語記録を同じトランザクションで処理し、同じ問題の再送で連続正解数を増やしません。新しい単語記録には256バイトの論理容量を計上し、既存の100MiB上限を維持します。実際の表・インデックス容量とは区別します。

導入時は、まだ保持されている回答詳細から記録を初期投入します。既に削除済みの古いテストの回答は復元できません。過去の回答時刻はトランザクション開始時刻なので、並び順の証拠には使いません。各回答が保存した総所得は正解のたびに増え、誤答や購入では減らないため、同じ単語の最後の誤答時点より総所得が多い直近7日以内の正解が2件以上ある場合だけ定着とします。総所得のない古い誤答が残っている単語は、順序を証明できないため未定着として解き直しに引き継ぎます。新しい2回連続正解で通常どおり定着します。導入後の単語記録は、期限切れのテスト・回答詳細を削除しても保持します。累計所得・支出・購入済みスタンプは変更しません。

公開切替時に旧採点処理がロック待機していても、回答のINSERTトリガーが定着記録と容量を同じトランザクションで更新します。関数の置き換えだけで実行中の古い処理が置き換わるとは扱いません。ガチャもINSERT時に新プロトコルと10万轟の額を確認するため、切替後に旧処理が旧額で購入を確定しません。

APIの契約は[api.md](api.md)、DBの境界は[rpc.md](rpc.md)、10万轟への価格変更は[WALLET_GACHA.md](WALLET_GACHA.md)を参照してください。追加の環境変数・サービス・依存関係はありません。

## 検証コマンド

テスト専用のループバックPostgreSQLを指定して実行します。環境ファイルの値は成果物やログへ出しません。

```sh
npm test
npm run build
NODE_ENV=test node --env-file=<local-test-env> tests/mastery-db.cjs
NODE_ENV=test TARGET_KGS_SOURCE_ROOT=<KGS01-gacha-100k>/prototype/v2 node --env-file=<local-test-env> tests/mastery-e2e.cjs
```

専用DBでの検証、公開クラウドDB、公開HTTP、実機Safariはそれぞれ区別して記録します。
