# Target — 学習ホームとリアタイHPバトル

## 対象

開発ブランチ feat/target-study-hub-quiz-battle-20261114 （基点：codex/target-study-v1）。
初期版は公開済み。以下の共通問題早押しルールは独立した新PRで検証し、既存DBの進行中試合がない場合にのみ切り替える。

## 学習ホーム
- 教材選択：Target 1900／英熟語 Target 1000／古文単語。
- 2×2ボタン：暗記・テスト／定着率・解き直し。
- リアタイバトル ボタン。その下に既存のランキング。
- ホームから重複するSection欄と「定着率 / 確認」行、ミス件数の大きな表示領域を撤去。
- 暗記を押すと専用Section設定ページに進み、開始すると従来の暗記画面を使う。既存テスト・定着率・解き直しのロジックは維持。

## リアタイバトル
1. 既存TargetからKGSセッションを毎回検証。ロビーでオンラインユーザー（約90秒以内のハートビート）を表示し、相手を指定して招待。
2. 双方が教材、開始/終了Section、同額の賭け金（仮想通貨「轟」、100轟単位）、初期HPを変更可能。HP候補は50/100/150/200/300。変更は必ず双方の承認を解除し、新しい設定バージョンで再承認。
3. 双方の明示的な承認が揃ったときだけ、PostgreSQLの単一トランザクションで各自の賭け金を確保（残高・上限確認）。
4. **共通問題の早押し形式**。試合ごとに1つの選択肢順・問題IDを保持し、2人へ同じ問題を配信。サーバー時刻で開始・締切を判定し、最初に正解した1人だけが相手へ5ダメージ。**不正解では自分のHPが10減り**、その問題での再回答はできない。0HPで決着。
5. 左右のHPゲージは中央を起点に対称表示。ユーザー名はゲージ上、円形ユーザーアイコンは下、合計賭け金は中央上。
6. 勝者に2人の合計賭け金を払い戻し。未成立・期限切れの中止なら、確保した金額を各自に返金。確定後の降参は相手が勝利。
7. サーバーは正解の選択肢、先着順、HP、勝敗、財布更新を確定。回答と承認には再送用UUIDを使い二重処理を防ぐ。対戦中は約480msのHTTP状態確認（ロビーは約2.6秒）。問題を1.6秒前に両者へ配信し、18秒の回答受付を設ける。最初の正解／両者誤答／時間切れを確定したあと約1.9秒で次の共通問題へ進む。

ユーザーのプロフィール写真は専用の認可済み画像連携がないため、最初のDraftでは名前の頭文字を円形アイコンに表示する。既存KGS非公開画像を許可なく取得しない。

## 既存データ保護
- 認証にはTargetとKGS間の既存サーバー専用秘密とセッションを使用し、ブラウザにserver secretを渡さない。
- PostgreSQLのtarget_private内にRLS付き専用テーブルを加え、public RPCもサーバーsecret検証を必須とする。
- 既存のウォレット履歴・2playerの結果とギャンブル撤去済み経路を保持し、新たなバトル会計のみ追記する。
- 既存2playerサッカーと同一ユーザーの同時資金拘束を新規トリガーで防ぐ。
- 金融処理は既存のグローバルDBロック 991101、上限検査、append-only領収記録、財務投影関数で管理する。

## 共通早押し画面（2026-11-14）
- 対戦中は「リアタイバトル」見出しと通常のページヘッダーを非表示にし、ホームに戻る最小操作、HPゲージ、4択と降参を画面内へ収める。動的ビューポート100dvhを使い、極端に長い語句だけは各選択肢内で読めるようにする。
- 早押し勝者は選択肢の上に緑の「⚔ 攻撃成功 +5」、相手は赤の「💥 被ダメージ −5」を短くスタンプ表示。両者誤答・時間切れはダメージなし。
- 共有ラウンドを保護された専用テーブルに1件ずつ保存し、正解IDと答えを一切ブラウザへ出さない。誤答後の連打、2人が同時正解した際の重複攻撃、過去リクエストの再送、古い画面によるV1の別問題生成を拒否する。
- 通信速度による表示差はあり得る。公平な結果判定はブラウザ側の計測時間ではなく、DBが受理した最初の正解を基準にする。
- 本番切替前に独立DBで両者同じ問題と同時正解競合、HP5/0、正解者と被害者の表示、既存の財務・定着・2player不変性を検証する。

## 2026-11-14：招待後設定・コンパクトUI・誤答ペナルティ復活

- リアタイバトル画面だけ通常の「暗記」ブランドヘッダーとフッターを非表示にし、最上段に「リアタイバトル」のタイトルとホーム・更新操作をまとめる。本文とログイン一覧の余白を小さくするが、通常のロビーリストは最低59pxのタップ行を保持する。
- 相手の「対戦する」を押すと、**その時点では教材、Section、賭け金、HPを選ばずに招待を送る**。サーバーは内部で仮のデフォルト値を保持するが、決定・賭け金の確保は一切しない。相手が「受ける」を押して初めて両者が対戦設定フォームへ進み、双方が各条件を提案・確認・承認する。設定変更では双方の承認をリセットする。
- 設定画面も通常ヘッダーを非表示にし、説明文や余白を減らす。教材、Section範囲、賭け金、初期HPをスマホで読みやすいサイズ（44px以上）にし、許可確認ボタンを近くに配置する。
- 共有早押し：先着の正解者が相手へ5HP攻撃。不正解者は自分へ10HPの減点。不正解では攻撃権は獲得できず、相手は正解を試みられる。両方誤答した場合は各自−10HPで次の問題へ進む。自傷のHP0でも対戦終了、勝者へ合計賭け金が一度だけ精算される。
- 緑の正解・攻撃スタンプと赤の被ダメージスタンプを維持。誤答直後の本人には専用の赤い「誤答 −10」スタンプを表示。DBは誤答情報をそのプレイヤーにだけ返すため、相手の個別回答内容が漏れない。
- DBマイグレーションは進行中の資金拘束試合0件の時だけ実行可能。現在のVercel Production版はデプロイ制限により旧画面互換フラグが一時的にfalse。新UIをProduction公開した後に安全ゲートを通してtrueへ切り替える。旧画面の招待と精算はそれまで維持する。
