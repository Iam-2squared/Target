# Targetの運用

## 対象と費用

GitHubは`Iam-2squared/Target`、Vercelは`kgs-target`です。KGS01と同じ無料Supabase組織に、専用プロジェクト`wnamppudojisoshepavu`を東京リージョンで作成しました。2026-11-05の契約確認はFree、新規プロジェクト見積もりは月額0です。Vercelは既存Hobbyチームを使用し、有料機能・追加同時ビルド・従量課金・有料ドメインは設定していません。無料枠の制限時は停止・制限される運用です。

KGSの予定・写真・チャットをTargetへ複製しません。TargetがKGSへ依頼できるのは、既存の番号とPINの照合、およびTarget専用セッションの検証・失効です。連携専用の秘密を使い、KGSのDB・管理者・セッション秘密をTargetへ渡しません。

## 環境設定

`.env.example`が設定名のテンプレートです。実際の値はVercelの非公開設定で登録します。公開プレフィックスや静的ファイルへ秘密を入れません。`TARGET_RPC_SECRET`、`TARGET_COOKIE_SECRET`、`KGS_TARGET_INTEGRATION_SECRET`は、それぞれ十分長い独立した乱数です。連携秘密だけをKGS側の同名設定と共有します。

Supabaseの公開可能なキー自体には成績DBの読書き権限を与えません。サーバーだけが知るRPC秘密をDBで照合し、DBにはそのSHA-256だけを保存します。privateスキーマのテーブルを直接公開せず、許可されたRPCだけがトランザクション内で成績を更新します。公開APIの採点は毎回KGSのTarget専用セッションを確認します。

設定不足や通信失敗で、ローカル保存を共有成績として見せることはしません。ゲスト練習は明示的に記録対象外です。ランキングはTargetでテストに参加したユーザー名と正解数のみを表示し、出席番号・内部ID・PINを返しません。

## ローカル確認

`npm ci`、`npm run build`、`npm test`を実行します。実HTTPによる統合テストは`npm run test:e2e`です。専用のローカルPostgreSQLとKGSテストサーバーを使用し、実際の個人情報やクラウド秘密をテスト成果物に含めません。テスト用の環境変数とコマンドは検証記録を参照してください。

## 教材

教材の出典、全2900項目の検証、再取り込み手順は[materials.md](materials.md)にあります。元PDFや取得したWebページ全体、記事の説明文は公開リポジトリに含めません。

## 変更時

採点はブラウザが送った得点を信用せず、保存した設問と選択肢でサーバーが判定します。同じ回答の再送で得点を増やさず、別ユーザーのテストへ回答できないことを確認してからデプロイします。KGSのBAN・PIN変更・共通コード変更がTarget側にも反映することを回帰確認してください。

公開URL・コミット・デプロイ・実測の検証範囲は、作業完了時に検証記録へ追記します。
