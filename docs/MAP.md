# 500×500の共有マップ

マップはTargetの専用DBに保存し、暗記で得た轟と同じ残高を使います。空きマスは1マス100轟、ほかの人のマスは1マス1,000轟で自分の所有へ変更できます。自分のマスの色変更は無料です。元の所有者への払い戻しはありません。色は固定8色、座標は内部で0〜499です。

## 台帳と整合性

`target_private.map_cells`は購入済みマスと現在の所有者を保存します。主キーは(x,y)、所有者はTargetプロフィールのIDです。`map_purchases`はメンバー・操作UUIDを主キーとする不変の購入履歴で、空きマスの購入数×100＋他人から取得したマス数×1,000を記録します。総所得を変えずに`profiles.spent_points`へ支出を加えるため、既存ガチャもマップ利用後の残高を使います。

支出の制約は100轟単位へ広げ、負数・総所得を超える支出を引き続き拒否します。`wallet_snapshot`の`spent`は全支出、追加の`mapSpent`はマップ履歴の支出合計です。ガチャの購入履歴・確率・価格・関数本体は変更しません。クライアントは`spent = ガチャ履歴の支出 + mapSpent`を確認します。

購入は採点・ガチャと同じ991101ロック、その後にマップ状態行のロックを使います。残高と現在の所有者ごとの価格を確認してから、所有マス、画像行、支出、不変の履歴、リビジョンを同じトランザクションで更新します。見積りの後に所有者が変わり`maxCost`を超えると、何も変更せず価格の再確認を求めます。応答が途切れた場合も同じUUID・内容で再送すると一度だけ課金します。同じUUIDで内容を変更すると409です。再送は過去の色や所有権を再適用せず、その後の取得結果を保持します。

## 非公開RPC

`public.target_map_rpc(secret, action, input)`は既存のサーバー資格情報を照合してから入力・台帳を扱います。ブラウザーの公開キーだけでは操作できません。データ表と内部関数はprivateスキーマに置き、RLSを有効にし、匿名・authenticated・service_roleの直接利用を許可しません。公開RPCは通常のKGSサーバーを通し、本人のIDと名前はセッションから渡します。

大きな正方形も扱えるよう、このRPCだけ`statement_timeout=25s`とし、ほかの関数やロール全体の設定は維持します。

共通入力は`memberId`と`name`です。

- `state`：任意の`revision`（0〜JavaScriptの安全な最大整数）。幅・高さ500、`unitPrice=100`・`overwritePrice=1000`、リビジョン、パレット、残高を返します。
- `quote`：`shape`と整数の`color`(1〜8)。`count`・`newCount`（空き）・`ownCount`（自分）・`takeoverCount`（他人）・`cost`を返します。全選択が1人の所有なら`ownerName`を返し、それ以外はnullです。
- `buy`：同じ`shape`・`color`、`requestId`、`maxCost`（100の倍数、最大250,000,000）、`expectedUnitPrice=100`・`expectedOverwritePrice=1000`。不変の購入数・取得数・金額と最新残高・リビジョン、`replayed`を返します。

形は次の3種類だけです。

- `{type:'cell',x,y}`
- `{type:'line',x1,y1,x2,y2}`：端点を含むBresenhamの直線。最大500マス。
- `{type:'square',x,y,size}`：左上と一辺のマス数。1〜500、盤面外は拒否。

正方形はSQLでまとめて展開し、書込みと画像再生成は集合演算を使います。マスごとのSQL往復はしません。購入前の見積りは購入を確約せず、確定時に所有者・料金・残高を再確認します。

## 軽い描画データ

250,000個のDOMや所有者UUID一覧を送る代わりに、`map_rows`へ1行500バイトの色コードを500行保存します。0は空き、1〜8はパレットの色です。初回または未来のリビジョンを持つクライアントには、全250,000バイトを改行のないbase64として`pixels`に返し、`rows`は空配列です。

過去・現在のリビジョンを送ったときは`pixels=null`、その後に変更した行だけを`rows:[{y,pixels}]`で返します。各行の画像は500バイトのbase64、順序はy昇順です。変更なしなら`rows=[]`です。更新時は選択範囲が触れる行だけを再生成します。購入応答のリビジョンだけで古い画像を最新と扱わず、保持した画像のリビジョンから差分を読みます。

新しい表・画像行・購入履歴は既存の100MiB論理容量制限へ加算し、マップのレート行も期限切れ分を掃除します。APIは状態・見積りを毎分120回、購入を毎分60回までに制限します。確定済み購入の再送は新しい購入回数に数えません。

マイグレーション：`supabase/migrations/20261108073800_target_shared_map.sql`。

## ローカル検証

`NODE_ENV=test node --env-file=<非公開のloopback設定> tests/map-db.cjs`は、新しい専用PostgreSQLを使用します。空き・自分・他人の混在価格、取得後の所有権、再送・内容不一致、見積り後に所有者が変わる場合の価格上限、同時購入とガチャ／採点との残高競合、形と端、容量、RLSとprivate権限、不変の履歴を確認します。

500×500（250,000マス）の空き盤面は25,000,000轟、全マスの取得は250,000,000轟です。最大操作、全画像、500行の差分、再送の実測値は`test-results/map-db-results.json`へ記録します。計測は合成アカウント・ローカルDBの結果で、公開DBの実行時間を示すものではありません。
