# 2player — 同一プレイヤーの連続時間切れ3回による負け

2026-11-12。Target専用DBの正式な勝敗と精算ルールを追加する。KGS11th本体や旧カジノ機能には変更を加えない。

## 判定
- 1手番は従来と同じ**60秒**。期限までに有効なシュート入力がなかったプレイヤー本人の連続時間切れを+1。相手側のカウンターは別に持つ。
- そのプレイヤーが有効なシュートを確定すると、**その人だけ**カウンターが0に戻る。ネットワーク遅延によるリトライ、無効な入力、他人の操作では戻らない。
- 本人の手番における3回目の連続時間切れで、**直近の連続時間切れの間に相手が有効なシュートを行っている場合だけ**、時間切れした本人の負け。両者とも無操作のときには勝利報酬を発生させず、従来の10分無操作で中止・預かり金全額返却を維持する。
- 判定はクライアント時計に依存しない。Targetの保存済み手番・期限・受理済みシュートのみを参照する。60秒の処理中に適法に受理されたシュートは、計算が遅延してもタイムアウト扱いされない。
- ネットワーク再試行・多重ポーリングでも3回判定や払い戻しが二重に起こらないよう、既存の `991101` 全体ロックを継続利用。既存の1分おきの非公開CRONでも期限を更新する。

## 轟・ランキング
- 確定した勝者が二人の賭け金合計を受け取り、負けた人は自分の出資分を失う。処理は既存の `target_private.two_player_settle` を直接再利用し、台帳・残高・不変領収書・再実行防止を維持。
- 決着理由は `three_timeouts`。ゴール数は書き換えない。
- ランキングの時間切れ勝ちは**+1勝 / +1pt**、敗者は0ptで減点なし。従来の3–0/+3pt、3–1/+2pt、3–2/+1ptのルールは変更なし。
- 進行中の試合はカウンター0から判定を開始し、過去の試合結果は遡って書き換えない。
- Target UIではなく2player UIで各選手の `timeoutStreak` (0..3) を表示、完了時に理由を明示する。

1. Targetと2playerのGitHub Actions・ビルドを確認。Targetの隔離PostgreSQLテストは64 assertions PASS、hostedWrites=false。両者放置中止・現実の勝敗・リトライの二重精算・正常入力によるリセット・既存の3-0配点・エスクロー保存則を検証。
2. Target DB上でDDLを `BEGIN...ROLLBACK` する事前検査。必ず意図した専用Supabaseプロジェクトを指定し、先行ソースハッシュを再確認。
3. Targetをマージ・移行し、`supabase/tests/two_player_three_timeout_verify.sql` のread-only postflightで台帳・CRON・trigger・制約を監査。
4. 2player UIをマージして、Vercel `kgs-2player.vercel.app` を新しいビルドに切り替える。
5. iPhone・Android実機の表示とWi-Fi切断・再接続は別途手動確認が必要。自動テストを実機検証と混同しない。
