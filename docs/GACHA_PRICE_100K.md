# スタンプガチャの価格変更

2026-11-06。新しいガチャは1回100,000轟です。既存の購入価格10,000轟・保有スタンプ・支出・総所得・残高を変更しません。4種類の未所有から1個を選ぶ方式、重複なし、4種類で停止する動作は維持します。

`price`は現在の表示価格、購入応答の`cost`はその要求IDで実際に払った元の価格です。価格変更前に完了した要求IDの再送は、元の10,000轟のスタンプを返し、追加請求しません。再送は最新の残高と現在価格を同時に返します。購入は採点と同じ991101ロックとトランザクションで確定します。

## 価格の確認と移行

KGSブラウザは表示された`expectedPrice`を購入要求に含め、未確定の要求IDと一緒にsessionStorageへ保存します。応答消失後の再読込や429でも要求IDと価格を維持し、別の購入へ切り替えません。以前の保存形式の要求には10,000轟を使います。

Target DBは要求IDの完了済み照合を先に行い、未完了の購入は`expectedPrice=100000`だけ受理します。省略された価格は旧価格10,000轟の確認として扱います。古い画面が送る要求を10万轟で勝手に請求しません。`PRICE_CHANGED`は支出を発生させず、KGSが価格を読み直します。次の明示的なタップまで購入を再送しません。遅れて届く10,000轟の読み取りで、100,000轟の表示へ戻した価格を下げません。

Target・KGSの更新コードは10,000／100,000轟の表示と両価格の購入履歴に対応します。Targetサーバーは10,000轟の明示確認を旧DB互換の省略形へ変換するため、両アプリを先に更新しても、DBの価格変更前は既存の10,000轟購入が動きます。その後に専用Target DBの価格マイグレーションを適用します。

関数の置換だけでは実行中の古い関数を置き換えられません。移行は991101ロックを取り、private INSERTトリガーで新しいプロトコル印と`cost=100000`を要求します。移行前から待機していた古い10,000轟の処理はINSERTで拒否され、支出もロールバックします。既存行を変更するトリガーや、旧価格の新規購入を許す裏口はありません。
